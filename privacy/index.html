2. What data we collect

We only collect data that is necessary to provide the Service.

2.1 X account information

When you sign in with X via our authentication flow (using Supabase and X OAuth), we may receive:

  • Your X user ID
  • Your X handle / username
  • Your display name
  • Your avatar URL
  • Your email address (if X and/or your permissions allow)

We do not receive or store your X password.

2.2 Bookmark / content data

To provide the bookmark backup and organization features, we collect:

  • The posts you have bookmarked on X (content of the post, author handle, timestamps, and public metadata like media URLs)
  • Basic metadata we derive when syncing (e.g. internal IDs, sync timestamps)

These bookmark fields come from X’s internal Bookmarks GraphQL API (x.com/i/api/graphql), which the extension calls directly when you click sync. We do not read, scrape, or parse the HTML or DOM of the bookmarks page; the extension’s content script only displays the Eventually panel on that page.

We only process bookmarks for the X account that you explicitly connect to Eventually.

2.3 Browser session data (X sync only)

To call X’s Bookmarks GraphQL API on your behalf, the extension needs the same authentication X uses for your own requests. Using the browser webRequest permission, it observes outbound requests to X’s GraphQL API (/i/api/graphql) while you are logged in on x.com, and copies only these request headers when present: authorization, cookie, x-csrf-token. This data:

  • stays in your browser only (chrome.storage.session)
  • is used only to call X’s Bookmarks GraphQL API when you start a sync
  • expires automatically after about 30 minutes

We do not store your X password and never upload these session headers to Eventually servers. The extension does not capture headers from other (non-GraphQL) requests or from other websites, and it does not use them outside of syncing your bookmarks.

2.4 Billing and payment data

If you subscribe to reminder emails, payment is processed by Stripe. We may receive limited billing metadata from Stripe (for example, subscription status, customer ID, and plan). We do not store your full payment card number on our servers.

2.5 Usage and technical data

We may collect limited technical information when you use the extension or site, such as:

  • Browser type and version
  • Operating system
  • Approximate time and date of use
  • Error logs and basic analytics (e.g. which features are used, sync counts)

We do not attempt to track you across other websites.

3. How we collect data

We collect data in these main ways:

  • Directly from you: when you install the extension, sign in, configure email reminders, subscribe, or contact us.
  • From X when you sync: using your existing browser login, the extension syncs your bookmarks in these steps:
    1. You click sync in the extension.
    2. The extension reads session headers from your own X GraphQL traffic (see section 2.3).
    3. It calls X’s Bookmarks GraphQL API directly and parses the JSON response.
    4. The resulting bookmark data is sent to our backend; the session headers stay in your browser.

    To be explicit about what we do not do:

    • We do not use X’s official developer API for bookmarks.
    • We do not scrape or parse the bookmarks page HTML or DOM.
    • We do not intercept or read GraphQL response bodies from your page traffic; we only read outbound request headers for authentication.
  • From our infrastructure providers: Supabase (auth and database), our backend API, Stripe (billing), Resend (email delivery), and hosting providers may log technical events.

Browser permissions

The extension requests the following permissions:

  • webRequest: to capture your X GraphQL session headers for sync, as described in section 2.3. This is not general browsing surveillance; it only observes outbound requests to X’s GraphQL API.
  • X GraphQL host access (x.com / twitter.com GraphQL endpoints): to capture session headers and fetch your bookmarks via X’s GraphQL API.
  • storage: to save your Supabase login session (local) and your short-lived X auth headers (session).
  • identity: for the OAuth redirect used to sign in with X via Supabase.
  • tabs: to open or focus the bookmarks tab and clean up the OAuth redirect tab.
  • Backend / Supabase host access: to authenticate and sync data with Eventually services.
